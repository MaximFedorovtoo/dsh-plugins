# Codex Bridge — перенос проектов и чатов из OpenAI Codex в DeepSeek Harness

Плагин для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (DSH): находит проекты и треды приложения **OpenAI Codex** и переносит их в DSH — регистрирует папку проекта как рабочую область и создаёт чат с перепиской, который можно открыть и продолжить.

Ключевое отличие от «клонирующих» импортёров: **по умолчанию проект остаётся в своей исходной папке**. Никакой новой папки рядом не появляется и никаких `-2`, `-3` не создаётся — рабочая область DSH указывает на тот же каталог, в котором проект лежал в Codex. Режим копирования остался опцией (`importMode: copy`).

[English version](README.md) · [Инструкция по установке](INSTALL.md)

## Что делает

- Читает сохранённые проекты Codex (`~/.codex/.codex-global-state.json`) и треды (`~/.codex/sessions/**`), ничего в данных Codex не меняя.
- Импортирует проект и переписку в DSH:
  - **in-place (по умолчанию)** — рабочая область регистрируется по исходному пути проекта, файлы не копируются;
  - **copy** — проект копируется в `targetRoot` (по умолчанию `Documents/deepseek-harness/Codex`) вместе с `.git`, а повторный импорт обновляет **ту же** папку.
- Создаёт чат-сессию DSH с перепиской Codex (user/assistant) и прикрепляет её к рабочей области.
- Умеет **массовый импорт**: кнопка «Все чаты» у проекта переносит все треды, кнопка «Импортировать всё» — все проекты и все их чаты. На каждый тред создаётся свой чат; повторный запуск дописывает только новые сообщения.
- Повторный импорт того же проекта **дописывает только новые сообщения** в тот же чат, без дублей сессий.
- Ведёт манифест `.codex-import.json`, по которому узнаёт уже импортированный проект. В режиме in-place манифест лежит в папке проекта (это единственное, что плагин в ней создаёт); удаление манифеста превращает папку в обычную.

## Где это в интерфейсе

- Левая панель → иконка **Codex** → страница «Импорт из Codex»: список проектов и тредов, кнопка «Импортировать»/«Обновить», результат и кнопка «Открыть чат».
- Инструмент модели `codex_import` (`action: "catalog" | "import"`).
- Settings → Plugins: карточка плагина с иконкой и описанием.
- Маршруты панели: `GET /api/codex-import/catalog`, `POST /api/codex-import/import` (только владелец сессии).

## Установка

Пакет `dsh-codex-bridge`, DSH 0.2.x, чистый JavaScript без зависимостей и сборки. Способы — в [INSTALL.md](INSTALL.md), коротко:

```powershell
dsh plugin --profile desktop add 'github:MaximFedorovtoo/dsh-plugins#<commit>&path:/plugins/dsh-codex-bridge'
```

В PowerShell используйте `dsh --% plugin --profile desktop add "..."` — иначе `&` в адресе съедается обёрткой `dsh.cmd` (подробно в [INSTALL.md](INSTALL.md)).

или **Plugins → Add plugin** → `github:MaximFedorovtoo/dsh-plugins#<commit>&path:/plugins/dsh-codex-bridge`; или запустить `installer\install.cmd` (Windows, без git). После установки перезапустите DSH.

## Настройка

Строка `codex-import` в `cordis.patch.yml` профиля (или одноимённая строка в слое пакета):

| Поле | По умолчанию | Смысл |
|---|---|---|
| `importMode` | `in-place` | `in-place` — проект остаётся в своей папке; `copy` — копия в `targetRoot` |
| `codexHome` | `''` → `$CODEX_HOME` или `~/.codex` | Где лежат данные Codex |
| `targetRoot` | `Documents/deepseek-harness/Codex` | Куда копировать проекты в режиме `copy` |
| `maxTranscriptChars` | `1500000` | Лимит текста переписки (берутся последние сообщения) |
| `excludeNames` | `node_modules`, `.next`, `.nuxt`, `.turbo`, `.cache` | Что не копировать в режиме `copy` |

Пример включения режима копирования:

```yaml
- id: codex-import
  config:
    importMode: copy
    targetRoot: D:\CodexProjects
```

## Поведение импорта

- **Первый импорт (in-place):** рабочая область = исходная папка проекта; создаётся чат с историей; в папку пишется `.codex-import.json`.
- **Массовый импорт:** «Все чаты» у карточки проекта импортирует каждый тред проекта, «Импортировать всё» — все проекты целиком. Ошибки по отдельным тредам не прерывают остальные и попадают в итоговую сводку.
- **Повторный импорт:** та же папка, тот же чат; дописываются только новые реплики Codex (`appended` в ответе).
- **Первый импорт (copy):** папка `targetRoot/<имя проекта>`; если такая папка уже существует и это копия проекта (есть `.git` или манифест) — она переиспользуется и обновляется, а не получает суффикс `-2`. Суффикс появляется только если имя занято **другим** проектом Codex или посторонней непустой папкой.
- **Смена режима:** уже импортированный проект находится по манифесту, поэтому повторный импорт не создаёт вторую копию; но менять режим для одного проекта без удаления манифеста не рекомендуется.

## Ответ импорта

```json
{
  "ok": true,
  "updated": false,
  "projectId": "4e3573dd-…",
  "projectName": "сервер",
  "threadId": "01a0f78d-…",
  "targetDir": "D:\\projects\\сервер",
  "workspaceId": "…",
  "sessionId": "session-…",
  "sessionTitle": "Codex · сервер · Проверить доступность сервера",
  "sessionCreated": true,
  "appended": 0,
  "messages": 70,
  "copiedFiles": 0,
  "importMode": "in-place",
  "eventCount": 0,
  "attached": true
}
```

- `updated` — проект уже был импортирован и обновлён;
- `copiedFiles` — 0 в режиме in-place;
- `appended` — сколько новых реплик дописано в существующий чат;
- `importMode` — фактический режим;
- `attached` — чат прикреплён к рабочей области; иначе причина в `warning`.

## Ограничения

- Данные Codex только читаются. В режиме in-place плагин создаёт в папке проекта один служебный файл `.codex-import.json`.
- Обновление в режиме copy перезаписывает файлы версиями из Codex, но не удаляет файлы, которых в Codex уже нет.
- Если в треде нет текстовых сообщений, импортируется только проект (без чат-сессии).
- Дописывание в чат работает, только когда сессия не открыта агентом; иначе файлы обновятся, а в `warning` вернётся причина.
- Парсер чувствителен к формату логов Codex; при смене формата `src/codex-source.js` нужно обновить.
- Импорт в режиме in-place меняет рабочую область DSH, но не исходный код проекта.

## Проверки

- `test/target-dir.test.mjs` — самопроверка выбора папки: пустая папка переиспользуется, существующая копия проекта (`.git`) усыновляется, чужой проект и посторонняя непустая папка получают суффикс; манифест читается по id. Запуск: `node test/target-dir.test.mjs`.
- Синтаксис всех модулей — `node --check`.
- Установка из репозитория проверена на временном профиле DSH: `dsh plugin add` + строка `id: codex-import` в `dsh --profile <name> --dump-config`.
