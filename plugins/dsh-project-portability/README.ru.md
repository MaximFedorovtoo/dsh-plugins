# dsh-project-portability — переносимые проекты DSH

Плагин для DeepSeek Harness: выгружает проект целиком в **один файл `.dshpack`**
и восстанавливает его на другом компьютере — с файлами, всеми чатами, их
полной историей и вложениями. Работа продолжается в тех же чатах, без потери
контекста.

```
проект DSH (workspace)
├── файлы проекта            → project/...
├── все чаты проекта         → sessions/<nnnn>/meta.json + events.jsonl
├── вложения и файлы из чатов → attachments/...
└── описание архива          → manifest.json
                ↓
        project-2026-10-30.dshpack   (gzip + tar, один файл)
                ↓
   внешний диск → другой компьютер → project_import
```

| Плагин | Что делает | Где работает |
|---|---|---|
| `dsh-project-portability` | Экспорт проекта в один архив `.dshpack` и импорт на другом компьютере: файлы, все чаты с историей и вложения. | Windows, macOS, Linux |

## Что переносится

- **Файлы проекта** — полное дерево папки проекта (включая `.git`, если он есть);
  символические ссылки пропускаются с предупреждением.
- **Все чаты проекта** — каждая сессия со своим полным логом событий v4:
  сообщения, вызовы инструментов, результаты, заголовки, метаданные. При импорте
  создаётся новый чат с тем же содержимым, привязанный к новой папке проекта.
- **Вложения** — картинки и загруженные файлы, на которые ссылаются события чата.
  Хранилище DSH контентно-адресное, поэтому байты переносятся как есть и старые
  ссылки остаются валидными.
- **Регистрация проекта** — на новом компьютере проект появляется в сайдбаре DSH
  как рабочая область, а чаты — в ней.

## Что НЕ переносится (осознанно)

- **Spill-файлы** (очень длинные выводы инструментов, выгруженные во временную
  папку процесса). Это временные данные самого DSH; после перезапуска они
  недействительны и на исходной машине. Чаты от этого не ломаются: в истории
  остаются обычные записи и превью.
- **Живые процессы и очереди** — архив статичен.
- **Абсолютные пути вне корня проекта** (например, ссылки на файлы в других
  папках) остаются как были: плагин переписывает только путь проекта.
- `.dsh`-настройки, ключи и креды — не входят в архив (это персональные данные).

## Установка

Плагин ставится так же, как остальные пакеты этого репозитория. Требования:
DSH 0.2.x (проверено на 0.2.1-rc.3), профиль `desktop` или любой другой.
Зависимостей нет: чистый JavaScript, ничего доустанавливать не нужно.

```powershell
# CLI: из этого репозитория по git-ссылке с подкаталогом
dsh plugin --profile desktop add 'github:MaximFedorovtoo/dsh-plugins#<commit>&path:/plugins/dsh-project-portability'
```

В PowerShell символ `&` ломается об обёртку `dsh.cmd` — используйте стоп-парсинг:

```powershell
dsh --% plugin --profile desktop add "github:MaximFedorovtoo/dsh-plugins#<commit>&path:/plugins/dsh-project-portability"
```

Или локальная папка: скачайте репозиторий, распакуйте и укажите
**Plugins → Add plugin** абсолютный путь к `plugins/dsh-project-portability`.
После установки — `Ctrl+R` в окне DSH (или перезапуск приложения).

Подробности и разбор ошибок — в [INSTALL.md](INSTALL.md).

## Как пользоваться

**Интерфейс.** В сайдбаре появляется страница **«Перенос проектов»**:

- список проектов с путями и количеством чатов, кнопка **Экспортировать** у
  каждого;
- блок **Импорт архива** — путь к `.dshpack` (с кнопками недавних архивов из
  папки экспорта) или ввод пути вручную.

**Инструменты модели** (можно попросить агента словами):

| Инструмент | Что делает |
|---|---|
| `project_list` | показать проекты, пути и число чатов |
| `project_export` | `project` + необязательный `output` → архив `.dshpack` |
| `project_import` | `archive` + необязательный `targetDir` → восстановить проект |

**Порядок переноса на другой компьютер:**

1. Экспортировать проект (`project_export` или кнопка в UI). Архив по умолчанию
   ложится в `%USERPROFILE%\.dsh\exports` (настраивается).
2. Скопировать `.dshpack` на внешний диск/флешку.
3. На новом компьютере установить DSH и этот плагин.
4. Импортировать архив (`project_import` или UI). Если исходный путь свободен,
   проект развернётся туда же; иначе — рядом с суффиксом `-2`; можно указать
   `targetDir` явно.
5. Нажать `Ctrl+R` — проект и все чаты появятся в сайдбаре; чаты открываются и
   продолжаются.

## Настройка

Строка плагина в `cordis.patch.yml` профиля
(`~/.dsh/profiles/<profile>/cordis.patch.yml`):

```yaml
- id: project-portability
  config:
    archiveDir: ""            # папка архивов; пусто = <DSH_HOME>/exports
    excludeNames:             # имена, пропускаемые при упаковке дерева
      - .dsh-portability.tmp
    includeSessions: true     # переносить чаты
    includeAttachments: true  # переносить вложения
```

Если проект очень большой, в `excludeNames` можно добавить `node_modules`,
`.venv`, `__pycache__`, `dist` — тогда архив станет меньше, но зависимости
придётся восстановить на целевой машине.

## Формат архива

`.dshpack` — обычный **gzip-тар** (открывается 7-Zip, `tar -tzf`):

```
manifest.json                     формат, версия, проект, список чатов
project/...                       файлы проекта
sessions/0000/meta.json           метаданные чата (id, заголовок, cwd, eventCount)
sessions/0000/events.jsonl        полный лог событий, по одному JSON на строку
attachments/objects/<xx>/<sha256> контентно-адресные вложения
```

При импорте плагин:

1. проверяет `manifest.json` (формат, версия, наличие чатов);
2. распаковывает файлы проекта, не выходя за пределы целевой папки;
3. для каждого чата создаёт новую durable-сессию через
   `ctx.sessionPersistence` с новым `cwd`, переписывая в событиях старый путь
   проекта на новый и старый id сессии на новый;
4. проверяет сессию холодным чтением (`open` + replay-валидация);
5. регистрирует рабочую область и привязывает к ней чаты;
6. восстанавливает вложения в хранилище.

## Ограничения и совместимость

- Формат архива версионирован (`formatVersion: 1`). Архив от более новой версии
  плагина старый плагин откажется читать с понятной ошибкой, а не «съест» молча.
- `engines.dsh`: `>=0.2.0 <0.3.0`. Внутренние API DSH могут меняться между
  минорными версиями — при обновлении DSH проверяйте импорт/экспорт.
- Импорт регистрирует **новые** сессии, а не восстанавливает старые id: в DSH
  сессии привязаны к `cwd`, поэтому новый путь = новый чат. Заголовки и история
  сохраняются.
- Файловые хэши в манифест не пишутся (архив проверяется целостностью gzip и
  чтением каждого файла при распаковке).
- Недоступные для чтения каталоги и файлы (например, папка с запрещающим ACL,
  оставленная тестом безопасности) пропускаются с предупреждением: остальной
  проект пакуется, экспорт продолжается. Фатально падает только недоступный
  корень проекта. Неудачный экспорт не оставляет недописанный архив.

## Проверка

```powershell
node test/tar.test.mjs
node test/archive.test.mjs
node test/remap.test.mjs
node test/host.test.mjs
node test/client.test.mjs
```

Живой roundtrip вёлся на реальном проекте: экспорт → импорт в новую папку →
1416 файлов байт-в-байт, 53 события чата с непрерывными `seq`, старый путь
полностью заменён новым, старая сессия валидна после холодного чтения.
