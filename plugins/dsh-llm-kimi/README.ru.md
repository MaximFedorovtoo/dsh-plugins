# Kimi для DeepSeek Harness — подписка и оплата по токенам

`dsh-llm-kimi` подключает модели [Kimi](https://www.kimi.com) (Moonshot AI) к DeepSeek Harness двумя полноценными провайдерскими маршрутами. Оба говорят на Anthropic-совместимом Messages-протоколе Kimi — том самом, который Moonshot документирует для сторонних инструментов (Claude Code, OpenCode, Codex). Поэтому в харнесс приходят потоковый текст, вызовы инструментов, рассуждения и картинки без прокси-конвертеров протокола.

| Маршрут | Что оплачивается | Откуда берётся ключ | Эндпоинт по умолчанию |
|---|---|---|---|
| `kimi-code` | Ваша **подписка Kimi Code** (та, что даёт Kimi Code CLI / Desktop) | [Консоль Kimi Code](https://www.kimi.com/code/console) → **Create API Key** | `https://api.kimi.ai/coding` (международный) / `https://api.kimi.com/coding` (Китай) |
| `moonshot` | **Оплата по токенам** на платформе Kimi API | [Платформа Kimi API](https://platform.kimi.ai/console/api-keys) → API Keys | `https://api.moonshot.ai/anthropic` (международный) / `https://api.moonshot.cn/anthropic` (Китай) |

Подписочный маршрут — тот, который нужен, если Kimi Code уже оплачен: запросы списываются из квоты подписки, а не из отдельных API-кредитов. Moonshot официально поддерживает такую схему в сторонних инструментах; этот плагин — адаптер для DSH.

## Модели

**`kimi-code` (подписка):**

| ID модели | Имя | Контекст (пресет) | Рассуждения |
|---|---|---|---|
| `k3.1-pro` | Kimi K3.1 Pro | 262144 (на Pro+ — 1048576) | `low` / `high` / `max`, по умолчанию `high` |
| `k3.1-pro-highspeed` | Kimi K3.1 Pro HighSpeed | 262144 (на Pro+ — 1048576) | думает всегда |
| `k3` | Kimi K3 | 262144 (на Pro+ — 1048576) | `low` / `high` / `max`, по умолчанию `high` |
| `k3-256k` | Kimi K3 256K | 262144 | `low` / `high` / `max`, по умолчанию `high` |
| `kimi-for-coding` | Kimi for Coding (K2.8) | 1048576 | `low` / `high` / `max`, по умолчанию `max` |
| `kimi-for-coding-highspeed` | Kimi for Coding HighSpeed | 262144 | думает всегда |

Контекст моделей K3 в подписке зависит от тарифа: Plus/Moderato получают 256K, Pro/Allegretto и выше — 1M. Пресет ставит консервативные 256K, которые доступны на любом платном тарифе; на старшем тарифе контекст поднимается в патче профиля (см. [Настройка](#настройка)). Доступность моделей тоже зависит от тарифа: подробности в [документации Kimi Code](https://www.kimi.com/code/docs/kimi-code/models.html).

**`moonshot` (оплата по токенам):** `kimi-k3.1-pro`, `kimi-k3.1-pro-highspeed`, `kimi-k3` — у всех 1M контекста и уровни `low` / `high` / `max`. Anthropic-совместимый Messages-эндпоинт Moonshot документирует семейство K3; старые K2 на этом маршруте не подключены.

Все модели каталога принимают **изображения** (они мультимодальные) и текст. Картинки прикрепляются в поле ввода как обычно: плагин превращает вложения в base64-картинки запроса.

## Установка

### Discover (рекомендуется)

Включите **Custom plugin indexes** на странице Plugins, добавьте адрес индекса

```
https://raw.githubusercontent.com/MaximFedorovtoo/dsh-plugins/main/index.json
```

и установите **Kimi provider** из списка.

### Git

```sh
dsh plugin --profile desktop add "github:MaximFedorovtoo/dsh-plugins#<commit>&path:/plugins/dsh-llm-kimi"
```

`<commit>` — SHA из [списка коммитов](https://github.com/MaximFedorovtoo/dsh-plugins/commits/main).

### Локальная папка / ручная установка в профиль

**Plugins → Add plugin** принимает абсолютный путь к этой папке. Когда профиль Desktop управляется приложением, эквивалентная ручная установка:

```sh
node scripts/install.mjs --profile desktop
```

Скрипт копирует пакет в `$DSH_HOME/profiles/desktop/plugins/dsh-llm-kimi` и добавляет одну insert-запись в `cordis.patch.yml` этого профиля (предварительно делая резервную копию файла). `node scripts/install.mjs --uninstall` убирает и плагин, и запись. После установки перезапустите DSH — патч профиля читается при загрузке.

## Подключение ключа

1. Откройте **Settings → Models**. Появятся две строки: **Kimi Code (подписка)** (`kimi-code`) и **Kimi API (оплата по токенам)** (`moonshot`).
2. Нажмите **Edit** у нужной строки и вставьте API-ключ. Ключ сохраняется write-only в хранилище credentials под `KIMI_CODE_API_KEY` или `MOONSHOT_API_KEY`; он не попадает ни в `cordis.patch.yml`, ни в лог сессии.
3. Откройте выбор модели в поле ввода и выберите модель Kimi (например, `Kimi K3.1 Pro`). Рядом с выбором модели появится переключатель уровня рассуждений.

Для CI и сценариев без интерфейса те же ссылки можно экспортировать в окружение:

```sh
export KIMI_CODE_API_KEY=...   # подписка
export MOONSHOT_API_KEY=...    # оплата по токенам
```

Файловый провайдер credentials ставит сохранённое значение выше переменных окружения, поэтому ключ, введённый в интерфейсе, всегда побеждает.

## Настройка

Значения по умолчанию живут в схеме плагина (`catalog.js`); в патче профиля переопределяются только нужные поля, остальное берётся из пресета:

```yaml
- id: llm-kimi
  config:
    providers:
      kimi-code:
        baseURL: https://api.kimi.com/coding   # подписочный эндпоинт для Китая
        models:
          - id: k3.1-pro
            contextWindow: 1048576             # тарифы Pro / Allegretto и выше
      moonshot:
        apiKeyEnv: MY_MOONSHOT_KEY             # своё имя ссылки на credential
```

Каждый провайдер принимает `displayName`, `baseURL`, `apiKeyEnv`, `authStyle` (`x-api-key` или `bearer`), `maxTokens` (по умолчанию 32768), `defaultContextWindow`, `streamIdleTimeoutMs` (по умолчанию 300000) и полный список `models`. Запись модели принимает `id`, `name`, `description`, `contextWindow`, `maxTokens`, `inputModalities` (`text` / `image`) и `reasoning` (`efforts`, `always`, `none`), а для `efforts` ещё `defaultReasoningEffort`. Список моделей заменяет пресет; записи с тем же id наследуют неизменённые поля из пресета.

Добавить модель, которую Kimi выпустит позже, — одна запись в патче: id, контекст и стиль рассуждений, после чего она появится в выборе модели.

## Как это устроено

- Плагин регистрирует оба маршрута в сервисе `llm` и объявляет их в каталоге configurable-провайдеров, поэтому страница Models правит подключение без перезапуска.
- Запросы идут на `{baseURL}/v1/messages` с `stream: true`, `max_tokens`, системным промптом верхнего уровня, сконвертированным списком инструментов и `output_config.effort` для моделей с выбираемым уровнем. Подписка авторизуется через `x-api-key` (стиль `ANTHROPIC_API_KEY` из Claude Code), платформа API — через `Authorization: Bearer` (стиль `ANTHROPIC_AUTH_TOKEN`).
- Ответ переводится чанк за чанком: блоки `thinking` становятся reasoning-дельтами, `text` — текстовыми дельтами, `tool_use` — вызовами инструментов. Подпись `signature` у thinking сохраняется в replay-состоянии адаптера и отправляется обратно без изменений, как требует Messages API Kimi.
- Имена инструментов проверяются по грамматике Kimi `^[a-zA-Z_][a-zA-Z0-9-_]{0,127}$` и отображаются обратно, поэтому инструменты DSH с необычными именами продолжают работать.
- Использование токенов (включая чтение и запись кэша) попадает в счётчики харнесса; ошибки приходят с обычными кодами (`AUTH`, `RATE_LIMIT`, `QUOTA`, `CONTEXT_WINDOW_EXCEEDED`, `TIMEOUT`, …).

Ни зависимостей, ни этапа сборки: чистые ES-модули, которые загружаются прямо в Node-рантайме DSH.

## Ограничения

- Авторизация — статический API-ключ. Браузерный OAuth-вход Kimi Code (`auth.kimi.com`) не реализован; вместо него создаётся ключ в консоли Kimi Code — Moonshot поддерживает такие ключи в сторонних инструментах.
- Видео не отправляется; изображения и текст — да.
- Доступность моделей и контекст в подписке контролирует Kimi. Запрос модели вне тарифа вернёт ошибку провайдера (обычно HTTP 403); лечится ключом/тарифом.
- Kimi списывает квоту подписки или API-аккаунта напрямую. Отдельной модели стоимости плагин не добавляет.

## Если не работает

| Симптом | Причина |
|---|---|
| `401` / `AUTH` | Ключ от другой платформы. Ключ консоли Kimi Code работает только на `api.kimi.ai/coding`, ключ платформы — только на `api.moonshot.ai/anthropic`. |
| `403` сразу после первого запроса | Тариф не включает эту модель или уровень 1M. Попробуйте `kimi-for-coding` / `k3-256k` или уменьшите `contextWindow` в патче. |
| `400` про контекст | Разговор превысил настроенное окно контекста. Сожмите контекст или поднимите `contextWindow` на тарифе, где он доступен. |
| `MISSING_CREDENTIAL` | Ключ не сохранён под ссылкой строки и не экспортирован в окружение. |
| Ключ введён, а строка всё ещё «не настроена» | Страница Models обновляется после перезагрузки; откройте Settings → Models повторно. |

## Удаление

**Plugins → Installed** → отключить/удалить бандл, либо `node scripts/install.mjs --uninstall` для ручной установки. Сохранённые API-ключи остаются в хранилище credentials; при желании удалите их на странице Settings → Models.
